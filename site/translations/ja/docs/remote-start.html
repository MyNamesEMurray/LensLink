リモート開始

モニターの裏に固定したスマートフォンを、「開始」をタップするためだけに取り外す必要はありません。アプリが開いていて待機中のときは、OBSがカメラを直接開始できます。

アプリを開いておく必要がある理由

iOSがカメラとLensLinkの待ち受けを動かすのは、アプリが画面に表示されている間だけです。以下の仕組みはすべてそのためにあります。アプリは開いていて待機中のときにスタンバイを通知し、そこから先はOBSが引き継ぎます。

Siriやショートカットがまずアプリを開くのも、スタンバイ中にスマートフォンが自動ロックを控えるのも同じ理由です。ロックされると待ち受けが停止してしまいます。セットアップ画面は1分後に暗くなり、緑ではなくアンバーで表示されます。ライブ中ではなく、待機中であることを示しています。

リモート開始はデフォルトでオンです。オフにするには、アプリのオプションでOBSからリモート開始をオフにします。

開始する4つの方法

ソースの接続時に自動で

準備ができたらスマートフォンのカメラを自動で開始はデフォルトでオンです。アプリを開けば、それ以上何もしなくても映像が表示されます。操作がぶつかり合うこともありません。OBSが自動開始するのはアプリに接続できるようになった直後だけで、停止を押した後に勝手に開始することはありません。

OBSから

アプリが接続されていれば、ソースのプロパティにあるスマートフォンのカメラを開始とスマートフォンのカメラを停止でいつでも操作できます。

ブラウザパネルから

http://localhost:9980のパネルには、アプリが待機中のときはカメラを開始、ライブ中は赤いカメラを停止が表示され、どちらの横にも自動開始のトグルがあります。

Siri、ショートカット、URLから

  • Siri（iOS 16以降）：「Hey Siri、LensLinkでストリーミングを開始」
  • ショートカット：カメラ配信を開始とカメラ配信を停止のアクションがあります。特定の充電器に接続したときに開始するなど、オートメーションで便利です。
  • URLスキーム：lenslink://startとlenslink://stop。iOS 15向けの方法ですが、どのバージョンでも使えます。

Siriのフレーズとサイドロードは相性がよくありません。再署名するとバンドルIDが書き換わり、コンパイル済みのフレーズデータとの関連が失われます。そのため、ショートカットからは同じアクションが動作するのに、Siriは応じません。App Store版を使うか、lenslink://startを使ってください。また、アプリを一度以上起動していること、設定 → Siriと検索 → LensLinkで「Use with Siri」がオンになっていることも確認してください。

シーンの切り替えでも開始・停止する

このソースがどこにも表示されていないときは切断を有効にすると、ソースを非表示にしたときにスマートフォンのカメラが停止し、表示すると再び開始します。自動開始と組み合わせれば、スマートフォンがエンコードするのは、どこかの画面に映っている間だけになります。

スクリプトから操作する

パネルのエンドポイントはシンプルなHTTP POSTです。

curl -X POST http://localhost:9980/api/control \
     -d '{"cmd":"start_stream"}'

curl -X POST http://localhost:9980/api/control \
     -d '{"cmd":"stop_stream"}'

スマートフォンが複数ある場合は、/api/sourcesで取得したソースIDを?src=として追加します。APIの詳細はブラウザパネルを参照してください。

スマートフォンでの表示

アプリが開いている、OBS未接続グレーの点、「未接続」。
アプリが開いている、OBS接続済み、カメラは待機中アンバーの点、「OBS接続済み・準備完了」。スタンバイ：リモート開始の準備ができています。
スタンバイのまま1分間操作なし画面が暗くなり、アンバーの復帰アイコンが表示されます。どこかをタップすると復帰します。待ち受けが止まることはありません。
開始後ライブ画面、緑の点、「ライブ」。

スタンバイ時に画面が暗くなるのは、アイドル表示が画面を暗くするの場合だけです。画面に触れている間やシートを開いている間は暗くなりません。
