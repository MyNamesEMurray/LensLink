远程启动

夹在显示器后面的手机，不该为了轻点一下“启动”就得取下来。只要 App 已打开且处于空闲状态，OBS 就能自己启动摄像头。

为什么 App 必须保持打开

iOS 只在 App 显示在屏幕上时才运行摄像头和 LensLink 的监听程序。下面的一切都源于此：App 打开且空闲时会宣告待机，之后交给 OBS 处理。

这也是 Siri 和快捷指令会先打开 App 的原因，以及待机就绪时手机会暂缓自动锁定的原因：锁屏会挂起监听程序。主界面在一分钟后变暗，显示为琥珀色而不是绿色：已就绪，但未直播。

远程启动默认开启。可在 App 的选项中通过从 OBS 远程启动将其关闭。

四种启动方式

来源连接时自动启动

手机就绪时自动启动其摄像头默认开启：打开 App，画面就会出现，无需其他操作。它也不会和你来回拉锯：只有当 App 刚变为可连接时 OBS 才会自动启动，而不是在你按下“停止”之后。

从 OBS 启动

只要 App 已连接，就可以使用来源设置中的启动手机上的摄像头和停止手机上的摄像头。

从浏览器面板启动

位于 http://localhost:9980 的面板在 App 空闲时显示启动摄像头，直播时显示红色的停止摄像头，旁边各有一个自动启动开关。

通过 Siri、快捷指令或 URL 启动

  • Siri（iOS 16+）：“嘿 Siri，用 LensLink 开始推流。”
  • 快捷指令：开始摄像头推流和停止摄像头推流操作，适合用在自动化中，例如手机连接到某个特定充电器时自动开始。
  • URL scheme：lenslink://start 和 lenslink://stop。这是 iOS 15 上的方式，而且在任何系统上都能用。

Siri 语句与侧载不兼容。重新签名会改写 Bundle ID，使编译好的语句数据失去对应：即使同一操作在快捷指令中可用，Siri 也会拒绝执行。改用 App Store 版本，或 lenslink://start。另外，确认 App 至少启动过一次，并且在设置 → Siri 与搜索 → LensLink 中允许 LensLink 与 Siri 搭配使用（英文界面中的“Use with Siri”）。

切换场景也会启动和停止

启用此来源未在任何位置显示时断开连接后，隐藏来源会停止手机摄像头，重新显示则会再次启动。配合自动启动，手机只在画面出现在某处时才进行编码。

用脚本控制

面板的接口是一个普通的 HTTP POST：

curl -X POST http://localhost:9980/api/control \
     -d '{"cmd":"start_stream"}'

curl -X POST http://localhost:9980/api/control \
     -d '{"cmd":"stop_stream"}'

有多台手机时，把 /api/sources 中的来源 id 作为 ?src= 加上。完整 API 见浏览器面板。

手机上会看到什么

App 已打开，OBS 未连接灰色圆点，“未连接”。
App 已打开，OBS 已连接，摄像头空闲琥珀色圆点，“OBS 已连接，就绪”。待机：远程启动已就绪。
待机状态下一分钟未操作屏幕变暗，显示琥珀色的唤醒图标。轻点任意位置即可唤醒；监听程序始终不会停止。
已启动直播界面，绿色圆点，“直播中”。

只有当空闲显示设为调暗屏幕时，待机才会变暗；你正在触摸屏幕或打开了面板时则永远不会变暗。
