Connect OBS to your phone

One TCP connection does everything: video, camera controls, clock sync and status. It runs over your local network, or over the USB cable through Apple's own device service. Nothing goes through the internet.

The short version

  1. On the phone, open LensLink

    Pick your lens, resolution, frame rate and codec, then tap Start camera stream. The Setup screen shows the phone's Wi-Fi address next to the status dot — tap it to copy.

    With Remote start from OBS on (the default), you can skip the tap: just leaving the app open and idle is enough, and OBS starts the camera itself.

  2. In OBS, add the source

    Sources → + → LensLink Camera. Give it a name — one source per phone.

  3. Point it at the phone

    Wi-Fi: open the Phone dropdown and pick your device, or type the IP the app is showing.

    USB: plug the cable in and set Connection to USB cable.

Video appears within a second or two. Closing or backgrounding the app blanks the source — iOS suspends camera capture for apps that are not on screen.

Wi-Fi

The phone and the computer must be on the same network, and that network must not block device-to-device traffic. Guest networks, "client isolation" on an access point, and some university or office networks do block it; a phone hotspot with the computer joined to it does not.

Finding the phone by name

While the app is open it advertises itself over Bonjour, and the source's Phone dropdown lists whatever it finds. If your phone is missing from that list but you can still type its IP, the app is almost certainly missing the Local Network permission, which iOS requires for the name broadcast:

  • Allow it when the app asks, or
  • Turn it on in Settings → Privacy & Security → Local Network → LensLink.

Typing the IP address works regardless of that permission.

When the address changes

Phones get a new DHCP lease from time to time, which is why picking the phone by name is worth the permission prompt. If you type addresses instead, reserve one for the phone in your router, or check the app's Setup screen again after a reconnect.

USB

USB is the recommended connection for anything that matters. It needs no network at all, holds the lowest and steadiest latency, and charges the phone while it streams — which matters, because encoding video is one of the more demanding things a phone can do.

  1. Windows only: install iTunes

    It provides Apple's device driver. Without it the source reports no device on USB, no matter what cable you use.

  2. Plug the phone in and tap Trust

    The phone must be unlocked for the prompt to appear. A charge-only cable will not do — it has to be a data cable.

  3. Set Connection to "USB cable"

    Leave USB device on Auto (first available) unless you run more than one phone.

Pinning a phone to a source

With several phones plugged in, set each source's USB device to a specific device instead of Auto. The same phone then always feeds the same source, whatever order things were connected in. A source pinned to a device that is not plugged in waits for it and says so.

Several phones at once

Add one LensLink Camera source per phone. Each has its own connection, its own controls and its own health readout, and the browser panel grows a tab per source so one page controls them all.

One phone feeds one source at a time. A second source aimed at the same device reports that the device is already in use. The exception is Disconnect when this source isn't shown anywhere: a hidden source releases the phone, so a Camera source in one scene and a Screen source in another can share a single device.

Reading the Status field

Every LensLink source has a Status line at the top of its properties. It is the fastest diagnostic in the product — it names the exact stage that is failing.

Connected: …Streaming. The line carries the device, resolution, frame rate and measured latency.

Keeping the connection healthy

  • Watch the numbers. OBS's status bar shows a live line per phone: LensLink: iPhone 60 fps · 11.9 Mb/s · 43 ms. View → Docks → LensLink gives the same thing as a panel with one row per source.
  • Congestion is handled for you. If Wi-Fi congests, the app briefly lowers quality and recovers, rather than piling up latency you then have to wait out.
  • Save the phone's battery. Turn on Disconnect when this source isn't shown anywhere and the phone stops encoding whenever the source is hidden, reconnecting when it is shown again.
  • The stream is unencrypted on your local network. It is designed for trusted home and studio networks, not for a shared public one.

If it will not connect

Work down this list before anything else:

  1. Is the app on screen on the phone? iOS suspends its listener otherwise.
  2. Is the phone unlocked?
  3. Wi-Fi: are both devices on the same network — not one on 5 GHz guest and one on the main SSID?
  4. USB: is it a data cable, and did you tap Trust?
  5. Does the Status field name a stage above? Follow that row.
