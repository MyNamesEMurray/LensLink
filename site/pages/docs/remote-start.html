Remote start

A phone clamped behind a monitor or on a rig should not have to come down just so somebody can tap Start. While LensLink is open and idle, OBS can start the camera for you.

Why the app has to be open

iOS only runs the camera — and LensLink's listener — while the app is on screen. A backgrounded app cannot capture video, and a suspended one cannot answer the network. That single platform rule is the reason all the machinery below exists: the app announces itself as standby when it is open and idle, and OBS takes it from there.

It is also why the Siri and Shortcuts paths open the app first, and why the phone holds its idle timer while standby is armed — auto-lock would suspend the listener and end remote start. The Setup screen dims a minute in, in amber rather than green, to say "armed, not live".

Remote start is on by default. Turn it off with Remote start from OBS in the app's Options.

The four ways to start

Automatically, when the source connects

The LensLink Camera source's Start the phone's camera automatically when it's ready option is on by default. Open the app — by hand, with Siri, or from a Shortcuts automation — and the video appears in OBS with no further input.

It will not ping-pong with you: OBS auto-starts only when the app has just become reachable, not after you deliberately pressed Stop.

From OBS

The source's properties have Start camera on the phone and Stop camera on the phone buttons, which work whenever the app is connected.

From the browser panel

The panel at http://localhost:9980 shows a Start camera button whenever the app is connected but idle, and a red Stop camera button while it is live. Beside each is an Auto-start toggle that flips the same setting as the properties checkbox.

From Siri, Shortcuts or a URL

  • Siri (iOS 16+): "Hey Siri, start streaming with LensLink" opens the app and starts the camera.
  • Shortcuts: the Start Camera Stream and Stop Camera Stream actions are available for automations — for example, starting the stream when the phone connects to a specific charger.
  • URL scheme: lenslink://start and lenslink://stop, from an "Open URL" action. This is the iOS 15 path, and it works on every version.

Siri phrases and sideloading do not mix. Re-signing tools rewrite the app's bundle ID for free Apple IDs, which orphans the compiled phrase data — Siri answers with a generic refusal even though the same action works from the Shortcuts app. Use the TestFlight build for working phrases, or drive it with lenslink://start, which works everywhere. Also make sure the app has been launched at least once and that "Use with Siri" is on in Settings → Siri & Search → LensLink.

Scene switching starts and stops it too

Enable Disconnect when this source isn't shown anywhere in the source properties and hiding the source stops the phone's camera entirely, while showing it starts the camera again — automatic power management that follows your scene switches. Combined with auto-start it means the phone only ever encodes while it is actually on screen somewhere.

Scripting it

The panel's endpoint is a plain HTTP POST, so anything can drive it:

curl -X POST http://localhost:9980/api/control \
     -d '{"cmd":"start_stream"}'

curl -X POST http://localhost:9980/api/control \
     -d '{"cmd":"stop_stream"}'

With more than one phone connected, add the source id from /api/sources as a ?src= parameter. The full API is documented on the browser panel page.

What to expect on the phone

App open, OBS not connectedGrey dot, "Not connected".
App open, OBS connected, camera idleAmber dot, "OBS connected — ready". This is standby: remote start is armed.
Standby, untouched for a minuteThe Setup screen dims to save battery, with an amber wake icon. Any tap wakes it; the listener keeps running throughout.
StartedThe Live screen, green dot, "Live".

Standby dimming only happens when your Idle view is Dim screen, and never while you are interacting with the screen or have a sheet open.
