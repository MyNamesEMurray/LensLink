Browser control panel

The plugin serves a small control panel at http://localhost:9980: the same camera controls the app's Live screen has, in a browser window you can park beside OBS. It is the operator's vantage point — nobody has to touch the phone.

Opening it

  1. Make sure the panel is enabled: Tools → LensLink Settings → Browser control panel. It is on by default.
  2. Open http://localhost:9980 in any browser on the same computer.

It listens on loopback only. The panel binds to 127.0.0.1, so it is reachable from the computer running OBS and from nowhere else — not from your phone, not from the network. That is deliberate: it can start cameras and change settings, and it has no authentication.

The port is a plugin-wide setting (Panel port, default 9980). Change it if something else on your machine already uses that port.

What is on it

The controls appear in the same order as the app's Live panel, because they are the same controls:

  • Header — the LensLink title and a status pill with the dot, word and latency, in the shared palette. When lip-sync auto-calibration is running, a second pill shows its stage and offers Recalibrate while locked.
  • Source tabs — only when more than one camera source is live. Every request carries the selected source, so one page controls every phone.
  • Zoom, exposure (AE bias, or manual ISO and shutter), focus (AF or Lock with a lens-position slider), white balance (AWB or Lock with a temperature slider).
  • A chip row: Flashlight, Lens, Flip.
  • Mid-stream format changes — resolution, frame rate, codec and microphone.
  • Subject distance, while the green screen is running with depth assist.
  • Start camera when the app is connected but idle, and a red Stop camera while live, each with an Auto-start toggle beside it.

The panel polls the plugin and mirrors changes made on the phone, pausing while you are dragging something so it never fights your hand. A LensLink Screen source has no camera controls, and the panel says so rather than showing dead sliders.

The HTTP API

The panel is just a client of a small HTTP API on the same port, and so can anything else be — a stream deck, a script, a scene-switching automation. Every endpoint takes an optional ?src=<id> naming the source; without it, the plugin picks the first suitable one.

Reading state

RequestReturns
GET /api/sourcesEvery LensLink source: id, name, connected, standby, screen.
GET /api/statusThe plugin's own view: status text, plus screen, standby, connected, autoStart and the lip-sync sync stage.
GET /api/stateThe phone's last camera-state snapshot — the lens list, current zoom, exposure, focus, white balance, supported formats and so on. This is the same cache the source properties read, which is how all three surfaces stay in lock-step.

Sending commands

POST /api/control takes one JSON command per request and forwards it to the phone. Unknown commands are ignored by design, so a newer panel and an older app degrade rather than break. 

POST /api/control
{ "cmd": "zoom",          "value": 2.0 }
{ "cmd": "exposure_bias", "value": -0.5 }
{ "cmd": "exposure",      "mode": "manual", "iso": 400, "shutterSeconds": 0.004 }
{ "cmd": "exposure",      "mode": "auto" }
{ "cmd": "focus",         "mode": "locked", "lensPosition": 0.42 }
{ "cmd": "focus",         "mode": "auto" }
{ "cmd": "white_balance", "mode": "locked", "temperature": 5600 }
{ "cmd": "white_balance", "mode": "auto" }
{ "cmd": "flashlight",    "on": true }
{ "cmd": "flip" }
{ "cmd": "start_stream" }
{ "cmd": "stop_stream" }
{ "cmd": "set_format",    "resolution": "1080p", "fps": 60, "codec": "hevc" }
{ "cmd": "mic",           "id": "builtin:2" }
{ "cmd": "green_screen",  "on": true, "maxDistance": 2.5 }
RequestEffect
POST /api/autostartBody {"on":true} or {"on":false} — the same property the source's auto-start checkbox edits. An empty body is rejected rather than read as "false".
POST /api/recalibrateNo body. Starts a fresh lip-sync measurement.

Examples

# Start the camera on the only connected phone
curl -X POST http://localhost:9980/api/control -d '{"cmd":"start_stream"}'

# Zoom the source with id 2 to 3x
curl -X POST 'http://localhost:9980/api/control?src=2' -d '{"cmd":"zoom","value":3.0}'

# What is connected right now?
curl -s http://localhost:9980/api/sources

Turning it off

Tools → LensLink Settings → clear Browser control panel. The port closes immediately; the app and the source keep working exactly as before.
